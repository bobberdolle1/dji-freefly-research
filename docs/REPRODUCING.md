# Reproducing this research

Everything in `docs/` was derived from samples obtained **outside** this
repository. **No proprietary artefact is redistributed here.** This page explains
what runs without any sample, and how to verify the analysis independently with
your own legally obtained copy.

---

## 1. What runs with no sample at all

The test suite is self-contained. It uses derived test vectors, hashes,
normalised metadata and synthetic/replay fixtures — never a bundled proprietary
file.

```bash
git clone https://github.com/Rezovovich/dji-freefly-research
cd dji-freefly-research
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install pytest
python -m pytest tests/ -q
```

Expected from repository contents alone:

```
198 passed, 2 skipped
```

The two skips are deliberate local-strengthening checks, listed in §4.

The derived data is inspectable with no tooling:

```bash
cat research/generated/freefly_commands.json      # recovered command table
cat research/generated/command_corpus.json        # normalised FCC command corpus
```

## 2. Supplying your own sample (optional)

`samples/` and `work/` are **gitignored** and must stay that way. Place your own
legally obtained copy there; it will never be committed.

```bash
mkdir -p samples
cp /path/to/your/FF_v_1_00.apk samples/
```

**Verify it is the sample this research describes** before trusting any
re-derivation:

```bash
sha256sum samples/FF_v_1_00.apk
```

| | |
|---|---|
| Expected SHA-256 | `a6dc898ddcec0e9e13ab9c270835faea8a6d7961e7012e534361cdec0b9894ee` |
| Package | `com.dronehacks.app` |
| Version | `1.0` (versionCode 1) |
| Size | 10,719,960 bytes |

With the sample present the suite reports `200 passed, 0 skipped`: the CRC
fixture is re-derived from your decompile and the signing parser is run against
the real APK.

## 3. Re-deriving the analysis

Requires the toolchain (a portable JDK, jadx and apktool, fetched into
`work/tools/`). **Linux/macOS shells shown; the scripts assume bash.**

```bash
bash tools/toolchain.sh                    # JDK 17, jadx 1.5.2, apktool 2.11.1

python tools/baseline.py    samples/FF_v_1_00.apk work/baseline
python tools/signing.py     samples/FF_v_1_00.apk work/baseline

# apktool decode -> work/apktool/decoded (needed for the CRC cross-check)
"$JAVA_HOME/bin/java" -jar work/tools/apktool.jar d -f \
    -o work/apktool/decoded samples/FF_v_1_00.apk

# recover the command table
python tools/extract_duml_commands.py \
    work/apktool/decoded/smali_classes8/com/dronehacks/app/data/protocol/DroneCommands.smali \
    --builder work/apktool/decoded/smali_classes8/com/dronehacks/app/data/protocol/DumlBuilder.smali \
    --json research/generated/freefly_commands.json

# regenerate the command map document from that JSON
python tools/render_command_map.py \
    research/generated/freefly_commands.json work/apktool/decoded docs/COMMAND_MAP.md
```

Everything lands under `work/`, which is gitignored.

## 4. The two tests that skip without a sample

Both exist to *strengthen* a result that is already asserted without them:

| Test | Skipped because | What it adds locally |
|---|---|---|
| `test_reference_fixture_agrees_with_local_smali` | no decoded smali | Re-derives `tests/fixtures/crc_tables_from_sample.json` from your own decode, proving the committed fixture still matches the application |
| `test_real_sample_signing_block` | no sample | Runs the signing-block parser against the real APK |

Neither is required for `flylib` to be correct. The committed CRC fixture was
extracted from the sample and **verified byte-for-byte equal** to the tables
`flylib` generates from polynomials `0x8C` and `0x8408`; those tables are DJI's
CRC constants rather than the sample's code, and functionally equivalent tables
appear in the public `o-gs/dji-firmware-tools` corpus.

## 5. Determinism

- The test suite uses a fixed random seed where randomness is needed.
- `flylib.next_seq` starts at 1, matching the application's behaviour.
- Golden vectors in `tests/test_duml.py` are checked field-by-field against the
  smali rather than captured from the implementation, so a re-implementation
  bug cannot make them agree.
- `research/generated/*.json` is regenerated by the `tools/` scripts above.

## 6. If your decode differs

Report it as a discrepancy rather than adjusting a document to match. The
project's convention — see [`../CONTRIBUTING.md`](../CONTRIBUTING.md) — is that
corrections are made **where the original claim appears**, with the reasoning.
